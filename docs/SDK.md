# SDK: подключение своей игры

Портал не собирает и не хостит игры. Игра живёт у вас — на любом движке, любом языке,
любом хостинге. Портал загружает её в `iframe` и разговаривает с ней через `postMessage`.
Всё, что от игры требуется: подключить SDK и объявить свой origin.

Эталонная реализация — `apps/example-game` (слот на ванильном TypeScript). Она же
используется в тестах проекта, поэтому не может разойтись с этим документом.

---

## 1. Подключение

```html
<script src="http://localhost:3000/sdk/v1.js" async></script>
```

Скрипт самодостаточен: ни зависимостей, ни сборки, 16 КБ. После его выполнения в
`window.Casinos` лежит готовый объект.

Для проектов со сборкой есть пакет `@luciferus/sdk` — тот же код с типами:

```ts
import type { Casino } from '@luciferus/sdk'

const casino = window.Casinos as Casino
```

### Почему `async` — это нормально

SDK регистрирует обработчик сообщений синхронно при выполнении, а `async`-скрипты
задерживают событие `load` окна. Портал, в свою очередь, повторяет приветствие, пока не
получит ответ. Поэтому гонки загрузки здесь нет — но игра **обязана** дождаться SDK,
прежде чем обращаться к `window.Casinos`:

```ts
async function waitForCasino(timeoutMs = 10_000): Promise<Casino> {
  const startedAt = Date.now()
  while (Date.now() - startedAt < timeoutMs) {
    if (window.Casinos) return window.Casinos
    await new Promise((resolve) => setTimeout(resolve, 50))
  }
  throw new Error('SDK не загрузился')
}
```

## 2. Объявите origin игры

Портал адресует сообщения **точно** на origin игры и никогда в `*`. Поэтому origin нужно
объявить в манифесте — иначе порталу некуда здороваться, и игра не запустится
(портал вернёт 409 с объяснением, а не молчаливую ошибку).

```json
{
  "slug": "my-game",
  "title": "My Game",
  "embed": "https://my-game.example/play",
  "origins": ["https://my-game.example"]
}
```

Origin — это схема, хост и порт, **без пути**:

| Указано | Совпадёт с `https://my-game.example/play` |
|---|---|
| `https://my-game.example` | да |
| `https://my-game.example/play` | нет — это адрес страницы, а не origin |
| `https://sub.my-game.example` | нет — это другой origin |
| `http://my-game.example` | нет — другая схема |
| `https://my-game.example:8443` | нет — другой порт |

Игра без объявленного origin видна в каталоге, но кнопка «Играть» у неё неактивна.

## 3. Работа с балансом

```ts
const c = await waitForCasino()
await c.ready()

c.on('ready', ({ player, balance }) => ui.show(player.displayName, balance))
c.on('balance', ({ balance, delta }) => ui.render(balance))

const roundId = c.roundId()          // 'r-...' — уникальный идентификатор раунда

await c.bet(10, { roundId })         // списание
await c.payout(150, { roundId })     // начисление
await c.rollback({ roundId })        // возврат ставки, если раунд сорвался
```

### Раунд — это ставка плюс выплата

`roundId` связывает операции между собой. Он же обеспечивает идемпотентность: повтор
`bet` с тем же `roundId` не спишет деньги второй раз, а повтор `payout` не начислит
выигрыш дважды. Поэтому ретрай при сетевом сбое безопасен — просто повторите вызов.

Если выплата не удалась, а ставка прошла, вызовите `rollback` — иначе деньги останутся
у портала:

```ts
try {
  await c.bet(bet, { roundId })
  const win = evaluate(...)
  if (win > 0) await c.payout(win, { roundId })
} catch (error) {
  await c.rollback({ roundId }).catch(() => {})
}
```

### Правила, которые проверяет сервер

Игра может ошибаться, но сервер — нет. Что бы игра ни прислала:

- ставка вне `limits` игры будет отклонена (`limit_exceeded`);
- ставка больше баланса будет отклонена (`insufficient_funds`);
- выигрыш без ставки в том же раунде будет отклонён (`conflict`);
- выигрыш выше `maxWin` будет отклонён;
- повторная выплата по раунду будет отклонена.

Лимиты приходят в `Casinos.limits` и берутся из манифеста игры, а не из запроса.

## 4. Что доступно

| Свойство | Тип | Описание |
|---|---|---|
| `Casinos.balance` | `number` | Текущий баланс. Всегда из последнего ответа сервера |
| `Casinos.player` | `{ id, username, displayName } \| null` | Игрок |
| `Casinos.limits` | `{ minBet, maxBet, maxWin }` | Лимиты вашей игры |
| `Casinos.mode` | `'portal' \| 'mock'` | Портал или локальный кошелёк |
| `Casinos.isInsidePortal` | `boolean` | То же, что `mode === 'portal'` |
| `Casinos.gameSlug` | `string \| null` | Слаг игры |
| `Casinos.handshakeError` | `CasinoError \| null` | Заполнен, если договориться не вышло |
| `Casinos.history` | `HistoryEntry[]` | Последние операции — для отладки |

| Метод | Описание |
|---|---|
| `Casinos.on(event, handler)` | `ready`, `balance`, `error`. Возвращает отписку |
| `Casinos.ready()` | `Promise<CasinoSnapshot>` — завершение хендшейка |
| `Casinos.bet(amount, options)` | `Promise<RoundResult>` |
| `Casinos.payout(amount, options)` | `Promise<RoundResult>` |
| `Casinos.rollback(options)` | `Promise<RoundResult>` |
| `Casinos.refresh()` | Перечитать баланс с сервера |
| `Casinos.roundId()` | Сгенерировать идентификатор раунда |
| `Casinos.formatBalance(value?)` | `1420.5` → `C$1,420.50` |

### Почему баланс — число, а не строка

На сервере деньги ходят строками: там важна точность до копейки. Но SDK — это граница с
игровым кодом, который почти всегда делает с балансом арифметику, и строка ему мешает.
Поэтому `balance` — `number`. Истина всё равно на сервере: после каждой операции SDK
берёт баланс из ответа, а не считает сам.

## 5. Разработка без портала

Откройте игру по её собственному адресу, не в iframe. SDK это заметит и поднимет
локальный кошелёк в `localStorage` со стартовым бонусом.

```bash
# игра на :4000, портал не нужен вообще
bun run --filter=@luciferus/example-game dev
```

В мок-режиме доступно то же поведение, что и на сервере: ставка не уходит в минус,
выигрыш невозможен без ставки, повтор раунда идемпотентен, лимиты соблюдаются. Иначе
игра работала бы локально и падала в портале.

Внизу справа появится отладочная панель: баланс, кнопки начисления, журнал операций.
Отключить: `?casino-devtools=0`.

> **Если панель показывает «Хендшейк не удался»** — игра внутри портала работает на
> локальном балансе. Так быть не должно: значит, origin не объявлен или SDK не подключён.

## 6. Что происходит под капотом

```
Портал                                        Игра (iframe)
  │                                              │
  │  casino:init { nonce, gameSlug, portalOrigin }│
  ├─────────────────────────────────────────────►│   адресат — объявленный origin
  │                                              │
  │  casino:hello { nonce, sdkVersion, caps }    │
  │◄─────────────────────────────────────────────┤   игра не постит в *
  │                                              │
  │  casino:session { token, apiUrl, wallet, ... }│
  ├─────────────────────────────────────────────►│   адресат — origin портала
  │                                              │
  │                          POST /v1/game/bet   │
  │◄─────────────────────────────────────────────┤   Authorization: Bearer <token>
```

Четыре проверки, которые портал делает до выдачи сессии:

1. Сообщение пришло **из нашего iframe** (`event.source`).
2. `event.origin` объявлен в манифесте игры.
3. `nonce` совпадает с выданным порталом.
4. Слаг игры совпадает с запущенной.

Не прошла любая — игра остаётся без сессии, а портал показывает причину.

**Почему инициатор — портал.** Если бы игра начинала разговор, ей пришлось бы постить в
`*`, и любая страница-обёртка могла бы выпросить сессию. Сейчас игра вообще не знает, кто
её открыл, пока портал сам не представится.

**Про игровой токен.** Он подписан HMAC-SHA256, живёт два часа, привязан к одной игре и
одному игроку и отзывается выходом из аккаунта. Украсть его у игры бессмысленно: она и так
распоряжается только этим.

## 7. Почему деньги ходят по HTTP, а не через postMessage

Ставки и выплаты — идемпотентные, ретраибельные операции с журналом. Через `postMessage`
их пришлось бы изобретать заново: подтверждения, таймауты, восстановление после
перезагрузки iframe. HTTP даёт это бесплатно.

`postMessage` остаётся для того, что не двигает деньги: хендшейка и подталкивания баланса
(`casino:balance`), когда портал узнаёт об изменении со своей стороны.

## 8. Частые ошибки

| Симптом | Причина |
|---|---|
| Панель: `handshake_timeout` | SDK не подключён, или origin игры не объявлен |
| Портал: «Игра ответила с origin …, которого нет в её манифесте» | iframe уехал на другой домен |
| `limit_exceeded` при ставке в пределах лимитов из манифеста | Игра не перечитала манифест: лимиты берутся из БД, а не из файла |
| Баланс в игре не совпадает с порталом | Игра считает баланс сама вместо чтения из ответов SDK |
| Ставка проходит дважды | Игра генерирует новый `roundId` на каждый ретрай вместо переиспользования |
